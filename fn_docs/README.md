# PTCG 宝可梦卡牌对战智能体（方法论实战）

用一套"从零制胜"的打法流程，在 Kaggle 的宝可梦集换式卡牌（PTCG）人机对战平台上，从零练出一个能打天梯的卡牌智能体，并把这套打法本身的实战表现记录成复盘报告。同一套流程顺带为即将开赛的 GSK 药企经营对战赛做赛前功课。

## 工作流程

（从开工到收官，按实际顺序）

1. **装引擎**：在战役目录内建独立 Python 环境，安装 Kaggle 官方对战引擎（cabt）。这个引擎就是裁判——两位选手（智能体）各交一份代码，引擎逐回合喂给双方"现在场上什么样、你有哪些选项"，选手回"我选哪几个选项"，直到分出胜负。
2. **读引擎（六问）**：把引擎源码通读一遍，回答六个问题（分数怎么算/对手在哪影响我/出错怎么表现/时间怎么切/谁能看见什么/随机在哪）。答案落成两张表：世界参数表（这个游戏的规则本质）和受控坐标表（哪些量我能直接控制、哪些能间接影响、哪些只能观察、哪些纯随机）。
3. **搭判决池**：先造"裁判的裁判"——一个本地评测台。让同一份种子智能体自己打自己（应该约五五开，用来测随机噪声有多大），再对打两个官方自带的傻瓜智能体（必须稳定赢）。以后每次改动智能体，都先在这个台子上量出"到底变强了多少"再决定保留与否。
4. **上天梯（种子件）**：写一个"最傻但完整"的参赛智能体（贪心选项+默认牌组），打成 Kaggle 要求的提交包（main.py + 60 张卡的牌组清单），提交到真实天梯。目标不是赢，是把"提交→自动排位→对局→回放可下载"整条链路走通。
5. **采回放**：用 Kaggle 命令行把天梯对局的回放（包括别的队伍的）拉到本地资料库，登记来源。
6. **摸对手**：把回放按行为习惯聚类——哪些队开局激进、哪些保守，谁克谁，画成一张对手关系图。
7. **炼资产**：统计高分队伍在每种局面下的标准动作，做成"查表"——以后遇到类似局面直接照着高分答案打。每个数字都记录出处和样本量。
8. **闭环迭代**：把查表、观测、防御等模块装进正式智能体。每次只改一处，在判决池上量"净赚多少分"（赢了对手但自伤多少也要算），有提升才保留，输了就回滚。全部改动记台账。
9. **复盘报告**：把上述每一步的实测数字（天梯分数、胜率、对齐率）汇成一份报告，重点记录这套打法流程哪里顺、哪里卡——卡点反馈回打法文档本身，让它下一场比赛更好用。
10. **GSK 赛前功课**（与上面并行）：GSK 经营对战赛的引擎已公开，用同样的六问+判决池流程给它做预研包；每天探测它的正式赛站是否上线，上线即报告。

## 项目功能

- **本地对战台（判决池）**：一键跑自对弈/对锚点评测，输出胜率与噪声地板；对局可存成回放文件。
- **引擎解剖产物**：世界参数表、受控坐标表（每条结论带引擎源码行号）。
- **提交打包器**：把智能体+牌组打成 Kaggle 提交包，自动检查结构并本地试打一局。
- **种子智能体**：贪心规则版参赛件（首个上梯版本）。
- **回放采集器**：批量下载天梯回放入库登记。
- **对手聚类器**：回放→行为画像→对手关系图。
- **资产开采器**：高分回放→局面查表（含数字出处）。
- **正式智能体**：观测/控制/调度/清单/防御五层结构，带净账护栏；单变量迭代台账。
- **指标汇总**：天梯分数、胜率等实测数字统一落一份指标文件，报告只引用这份文件。
- **GSK 预研包**：GSK 引擎六问表+本地判决池冒烟+赛站上线探活。
