## 1. 游戏目标与胜负判定

**1.1 胜利四途径（reason 1–4）**

| reason | 语义 | 引擎产生点 | 实证次数（222 game） |
|---|---|---|---|
| 1 | 拿完自己的奖赏卡（0 张剩余） | `finishCheck` 0x11042 / `PokemonCheckup` 0x67ddc | 179（80.6%） |
| 2 | 回合开始时牌库 0 张（deck out 爆牌判负） | `TurnStart` 0x6845e–0x68475 | 2（0.9%） |
| 3 | 战斗场无宝可梦可补（清场判负） | `finishCheck` 0x11060 / `PokemonCheckup` 0x67d55 | 41（18.5%） |
| 4 | 卡牌效果直接决定胜负 | `EffectInstatnt` 0x756b2–0x75705 | 0（本 corpus 未出现） |

- 每局每 game 均以 `RESULT` 日志收束，`{result, reason}` 字段齐全（222/222，无中断局）。[A·source-binary §4][C·source-sdk §4][D·source-replays §1.1]
- reason 2 仅"回合开始的强制抽牌失败"判负；因卡牌效果抽不出牌不判负。[B·source-rulebook 一.1 p21][A·source-binary §4（TurnStart 判 `[P(cur)+0x94]==0`）]

**1.2 检查顺序（同帧多条件的裁决）**

- `finishCheck`（0x10fe0）对每玩家累计 score：先查"奖赏=0"（score+1, reason 1），再查"战斗场空且后备空"（对方 score+1, reason 3），双玩家重复后比较 score：score[0]>score[1] → 玩家 0 胜（`State+0x19=1`）；< → 玩家 1 胜（=2）；相等 → 平（=3）。[A·source-binary §4]
- 同帧同时触发 reason 1 与 reason 3 时，reason 取后写的 3；`TurnStart` 回合开始先跑同一扫描再单独判 reason 2；`PokemonCheckup` 里也跑一次并写 `[0x19]/[0x1a]`。[A·source-binary §4]
- 结果编码：`State+0x19` = 1/2/3 = 玩家0胜/玩家1胜/平；日志 `RESULT.result` = 0/1/2（= `[0x19]-1`）；`State.result`（SDK 字段）=-1 未结束/0/1 胜者/2 平。[A·source-binary §4][C·source-sdk §2.4/§4]

**1.3 实证分布**

- game 胜方 player0/player1 = 111/111（完全均衡）；先手 game 胜率 109/222 = **49.1%（无先手优势）**；首个 TurnStart 的 playerIndex==firstPlayer 222/222。[D·source-replays §1.1]
- 清场线（reason 3）占 **18.5%**，远高于"罕见"直觉，必须作为独立防线定价（详见 §7.4）。[D·source-replays §1.1]
- 每 game 帧数 min 21 / p25 123 / 中位 152 / 均值 145.6 / p75 180 / max 248；每 game 回合数中位 11（min 2 / max 26）；全 corpus 2496 回合。[D·source-replays §1.2]

**1.4 平局与 Sudden Death**

- 引擎平局：score 相等 → `[0x19]=3` → `RESULT.result=2`；bo3 中平计入 draw 格，reward 0/0。[A·source-binary §4][C·source-sdk §5.5]
- 规则书：同时胜利 → Sudden Death（新局每人只放 1 张奖赏卡）；一方以两种途径赢、另一方只以一种途径赢，前者直接获胜。[B·source-rulebook 一.1 p21]
- **冲突 C3**：引擎 finishCheck 以 score 相等判**平局**收束，无任何 Sudden Death 实现证据 [A]；规则书要求 Sudden Death [B]。裁决（A>B）：**按平局建模**（bo3 draw 格 0/0），Sudden Death 列入 §13 未决项（引擎覆盖未知，reason 4 卡效果分支可改写胜负但 0 样本）。

## 2. 牌表规则（Deck Construction）

**2.1 强制规则**

- 牌表**恰 60 张**（59/61 均违规）；Python 层双重点强制（`game.battle_start` 两副都须 60 否则 ValueError；cabt.py 对 `len(action)!=60` 判 INVALID），引擎侧再校验。[B·source-rulebook 一.1 p22][C·source-sdk §3.2/§5.3]
- **同名最多 4 张**，基础能量除外；同名判定：LV. 后缀不计名，名称后符号（ex、h 等）与所有者/地区形态前缀**计名**（Meowth / Alolan Meowth / Rocket's Meowth 算三个名字），Delta Species δ 不计名。[B·source-rulebook 一.1 p21–p22]
- **至少 1 张基础宝可梦**（Basic Pokémon）；引擎在 `SetupActivePokemon` 抛 `No Basic Pokemon.`（error 99）；无基础 = mulligan（对手每多一次 mulligan 可多抽 1 张）。[B·source-rulebook 一.1][A·source-binary §7.3][C·source-sdk §3.1]
- **ACE SPEC 整副牌只许 1 张（总共 1 张，非每种 1 张）**；引擎侧强制，Python 层不查。[B·source-rulebook 一.6 p25][C·source-sdk §5.3][E·source-cards §2.3（全库 29 张 aceSpec）]
- 4 张上限与 ACE SPEC 的引擎校验只回传 `StartData.errorPlayer>=0`+`errorType`，**errorType 取值无文档**，Python 层无法证实具体条款。[C·source-sdk §6.3]

**2.2 开局流程**

- 抛硬币决定先手 → 洗 60 张 → 抽 7 张 → 有基础则 1 只出战（Active）+ 最多 5 只备战（Bench）→ 顶 6 张作奖赏卡（面朝下）。[B·source-rulebook 一.1 p8/p7]
- 引擎侧：`DeckToPrize(state, player, n)` 发奖（调用点 `AfterSetupActivePokemon` 0x50c13/0x50c4a）；`BattleStart(deck0, deck1)` 的 deck0=先手、deck1=后手。[A·source-binary §3][C·source-sdk §3.2]

**2.3 数据陷阱（牌表/卡库侧）**

- **化石跨界坑**：7 张 Antique 化石（Antique Root/Cover/Plume/Jaw/Sail/Skull/Armor Fossil）是 **Item 卡**（cardType=ITEM）却携带 `hp=60 / pokemonType=2 / evolutionType=1(basic) / basic=true`；7 条 `evolvesFrom`（Lileep←Antique Root Fossil 等）指向这些 Item 名，在宝可梦索引中**悬空**——按名解析进化链必断。引擎对 pokemonType==2 的裁定：**免疫全部特殊状态、不能撤退、撤退费用记 0**。[E·source-cards §7.1/§1][A·source-binary §8]
- **名字非唯一坑**：1431 卡仅 1196 个 distinct 名（Bronzor×5、Applin/Charcadet/Deoxys×4）；238 条 evolvesFrom 按名解析有歧义；同名不同卡（两张 Beldum 分属 {M}/{P}，弱点抗性不同）。**任何按名的统计或查询必须改用 cardId**。[E·source-cards §7.2]
- megaEx 与 ex 标志的语义冲突见 §8.3 / 冲突 C4。

## 3. 回合结构

**3.1 回合骨架**

- 规则书三段式：①抽 1 张 → ②行动阶段（6 类动作任意顺序、可穿插）→ ③攻击并结束回合。[B·source-rulebook 一.2 p9]
- 引擎骨架：`TurnStart`（胜负面扫描 → `turn++` → 清动作计数 → `State+0x18=1` → 清回合内效果队列 → **牌库为 0 判负（reason 2）** → 推 `MainSelect`）→ `TurnEnd`/`TurnEnd2`（清 `State+0x32` 位段）→ `PokemonCheckup` → `PokemonCheckupEnd` → `TurnStart`。[A·source-binary §2.5]
- `State+0x08` = turn 回合计数（1=先手第一回合，2=后手第一回合…）；`State+0x0c` = turnActionCount（回合内动作计数，TurnStart 清零）。[A·source-binary §0][C·source-sdk §2.4]

**3.2 四件套"每回合限 1"的位段实现（`State+0x32`）**

| 位 | 字段 | 置位点 | MainSelect 门禁 |
|---|---|---|---|
| 0x01 | supporterPlayed 支援者 | 0x815bc | 0x66c8b |
| 0x02 | stadiumPlayed 竞技场 | 0x81500 | 0x66b9f |
| 0x04 | energyAttached 贴能量 | 0x6e698 | 0x66ab0 |
| 0x08 | retreated 撤退 | 0x80fcb | 0x67388 |
| 0x10 | 第 5 位（效果用） | 0x75699 | 0x662d4 |

清零点 `TurnEnd2` 0x6cdf0；位段 + 选项生成门禁双重保证。[A·source-binary §2.1]

**3.3 实证：动作层 0 违例、事件层可被效果豁免（222 game / 2496 回合）**

每回合 turnActionCount 分布 0–38、峰值 8、中位 12、>20 的回合占 18.4%（459 个）；**回合内编排空间远大于"四件套"**——大头是道具/能力/进化与效果链。[D·source-replays §2]

**3.4 先手首回合三禁 + 攻击豁免位**

1. **禁攻击**：`MainSelect` 0x669bb–0x669dd——`turn==1` 默认不生成 ATTACK 选项，除非招式带 `Attack+0xe bit 0x8`（"首回合可用"）标志。[A·source-binary §2.2] 实证 0/222 先手首回合攻击；后手首回合（turn==2）不受限，攻击 92 次。[D·source-replays §2][B·source-rulebook 一.2 p13]
2. **禁支援者**（先手玩家首回合）："The player who goes first cannot play a Supporter card on their first turn"。[B·source-rulebook 一.2 p12] 引擎落实**未在反汇编/回放中单列验证**（回放仅有每回合限 1 统计）——列 §13 未决项。
3. **禁进化**（双方各自首回合，除非卡面写明）：[B·source-rulebook 一.2 p11] 引擎落实未知（同上）。
- 规则书**未**限制先手首回合贴能量/打竞技场/撤退/用特性/铺怪。[B·source-rulebook 一.2]

**3.5 攻击即终局化**

- 攻击并结束回合，攻击后不能再做任何行动。[B·source-rulebook 一.2 p9] 引擎：`ConfuseProc`/`AfterAttack`（0x7f200）后不再生成行动选项；实证 Attack 动作每回合恰 1、0 违例。[A·source-binary §1.5][D·source-replays §2]
- 撤退后新出战宝可梦当回合仍可攻击。[B·source-rulebook 一.5 p12]

**3.6 后备上限与强制弃置**

- 备战上限默认 5（`PlayerState+0x255` 低 4 位，0→5，可被效果改写）；超限由 `PokemonCheckupEnd` 0x824c4–0x825d9 推 `SelectBenchMaxTrash` 强制弃到上限。[A·source-binary §2.5/§0][C·source-sdk §2.3（benchMax 字段）][B·source-rulebook 一.1 p7]

## 4. 伤害计算

**4.1 六步公式完整版（规则书步序 [B] 与引擎流水线 [A] 互证）**

1. 从攻击名右侧的基础伤害（printed damage）出发；**若攻击文本是"放置伤害指示物"，计算到此为止**——指示物不受弱点、抗性及任何其他效果影响，直接放置。[B·source-rulebook 一.3 p20 步 1]
2. 加算攻击方侧的伤害增益，即卡面标注 "(before applying Weakness and Resistance)" 的修饰：引擎累加进 **`State+0x100`**（`AttackDamage` 0x7eec6 读出 + `Attack.damage` 后送入 `CalcDamage`）。[A·source-binary §6.1][B·source-rulebook 一.3 步 2/一.7]
3. **弱点（Weakness）×2**：防守方对攻击方**属系**（=攻击方宝可梦 `energyType`，与实际贴附能量无关）有弱点则 ×2（现代标准倍率）。[A·source-binary 前置+§6][B·source-rulebook 一.3 步 3 p14]
4. **抗性（Resistance）−30**：有抗性则减 30（引擎固化常数；规则书原文是"按卡面印数削减"，MEGA 时代卡池印值恒 −30）。[A·source-binary 前置+§6][B·source-rulebook 一.3 步 4/二.2]
5. 加算防守方侧减伤，即 "(after applying Weakness and Resistance)" 修饰（在 `CalcDamage` 返回后、`AddDamage` 落 HP 前应用；承载字段未一一定位，候选 `Card+0x1c`/`State+0x104`）。[A·source-binary §6.3][B·source-rulebook 一.3 步 5]
6. 终值每 10 伤害放 1 个伤害指示物；**下限 0**（`CalcDamage` 内 `max(0,…)`，规则书为"终值 ≤0 不放指示物"）。[A·source-binary §6.2][B·source-rulebook 一.3 步 6]

- 完整顺序结论：`攻击基础值 + Σ(before-W&R 修饰)` → `×2` → `−30` → `max(0,…)` → `Σ(after-W&R 修饰)` → 落 HP。[A·source-binary §6]
- 小差异（实务等价）：引擎的 0 下限在抗性后、after 修饰前（`CalcDamage` 内）；规则书在终值步 6 下限。建模按引擎序（A 裁决）。[A·source-binary §6 vs B·source-rulebook 一.3]
- 双属性：任一属性命中弱点/抗性即生效；同一攻击既触弱点又触抗性时**先弱点后抗性**（与引擎 ×2→−30 链一致）。[B·source-rulebook 一.3 p35][A·source-binary §6]
- W/R **只对出战宝可梦生效**；对备战宝可梦的伤害一律不加不减——卡文本高频括注 "(Don't apply Weakness and Resistance for Benched Pokémon.)"（64 处）。[B·source-rulebook 一.3 p14][E·source-cards §6]

**4.2 效果伤/指示物豁免**

- "放置伤害指示物" ≠ "造成伤害"：跳过 W/R 与**一切**修饰效果（含减伤）。[B·source-rulebook 一.3/一.7]
- 引擎记账：指示物效果（如 Dragapult ex "Phantom Dive" 对对手备战任意分配 6 指示物）以 `HP_CHANGE.putDamageCounter=True` 记录（1 指示物=10 HP），全 corpus 1543 次 −10、84 次 −30、16 次 −20 皆属此类，**不是毒伤**。[D·source-replays §4][C·source-sdk §4]
- 反例语义差：毒/烧/混乱自伤在引擎内以 `AddDamage` 落 HP、日志 `putDamageCounter=0`（记为伤害而非指示物）[A·source-binary §1.1]，与规则书"放指示物"表述在 HP 数值上等价，但**指示物类卡效（计数/移除指示物）的判别必须以 `putDamageCounter` 标志为准**（冲突 C9，见 §11）。

**4.3 W/R 值域与分布（1196 宝可梦，[E·source-cards §2.4]）**

- 弱点分布：{R}Fire 244、{F}Fighting 211、{L}Lightning 183、{G}Grass 159、{D}Darkness 113、{W}Water 112、{M}Metal 91、{P}Psychic 44、**无弱点 39（全部 {N}Dragon）**；**没有任何卡以 {C}/{N} 为弱点值**。
- 弱点主轴：{G}→{R}168、{R}→{W}112、{W}→{L}112（另 46 弱 {M}）、{L}→{F}81、{P}→{D}113、{F}→{G}88、{D}→{G}71、{M}→{R}76、{C}→{F}82。
- 抗性仅两值：{F}Fighting 187、{G}Grass 76、无抗性 933（抗 {G}=Metal 全体 76 张；抗 {F} 集中 Psychic 117）。其余 8 个属性从未出现在抗性栏。
- W/R 字段只存属性码，**倍率/量值（×2/−30）不在数据里**。[E·source-cards §7.4]

- **4 例残差全解**：Corkscrew Punch 10→40 / 10→80(W) / Power Gem 50→160(W) / 10→40，恰为 `(base+30)×W`——场上道具 **Premium Power Pro**（"本回合己方 {F} 攻击 +30，弱点/抗性结算前"）逐例在同回合打出。**加成层在弱点乘算之前，与六步公式步 2 一致**。[D·source-replays §6][E·source-cards（卡文本）]
- 同类"before W&R"增伤例：Voltaic {L} Energy 增伤 +20（W/R 计算前）。[E·source-cards §3]

**4.5 可变伤害技红线**

- 卡库 `damage` 是裸整数，对可变伤害**系统性低估**："Flip 4 coins. 30 damage for each heads"（Comet Punch）**记 0**；"+N more damage" 技只记基数；效果攻击的 printed base 在 49/81 抗性案例中不可用。[E·source-cards §7.5][D·source-replays §6]
- 红线：**伤害预测禁止单用 damage 字段**，必须以效果文本为条件（掷币期望、指示物、缩放类）；0 伤效果技 429 条全部带效果文本，最大 printed 350（Geobuster），全量均值 52.9/仅正伤 70.0。[E·source-cards §4.1]
- 另有 `CardMaster+0x5==4`（Mega ex）+ 伤害 ≥ 0xf0（240）的 `AddDamage` 特判（0x55cb0–0x55cbc），语义未定论——列 §13 未决项。[A·source-binary §6.3]

## 5. 奖赏数学（Prize Math）与 J 目标函数定稿

**5.1 1/2/3 分支实现（`KOProc3` 0x6ebd9–0x6ec80）**

- 按被 KO 卡的 `pokemonType`（卡框）分派：普通=1 张 / 3（ex）=2 张 / 4（Mega Evolution ex）=3 张（`cmp al,0x3/0x4` + `lea edx,[rdx+rdx*1+0x1]` 直读）。[A·source-binary §3][C·source-sdk §2.10][B·source-rulebook 一.6]
- 修正字段：`ecx = edx + Card+0x69(int8)`，再按 `Card+0x6b bit0x20`、`Card+0x6a`、`Card+0x6c bit5`、`Card+0x6c bit4` 做加减——承载"少拿/多拿 1 张"类效果（如 Legacy Energy "takes 1 fewer Prize card"，整局一次）；`ecx<=0` 或 `Card+0x6c bit0` 置位则跳过领奖。[A·source-binary §3]
- 领奖方 = `1 - Card+0x44`（KO 宝可梦的对手）；`SelectPrize` 内 `flag!=0` 时先推 `CoinPrize` **掷币决定张数**，再 `SelectedPrizeTarget` 择张。[A·source-binary §3]

**5.2 穷举验证（1171 领取簇 / 1176 KO / 222 game）**

- 领取分布：1 张 722 簇 / 2 张 354 簇 / 3 张 95 簇（合计 1715 张；单帧最多 3 张，多 KO 簇合计可达 6 张）。
- KO 构成：normal 688 / ex 366 / megaEx 122。
- 簇级验证（1110 簇）：**1049 簇（94.5%）严格满足 Σ奖赏值==领取张数**；61 簇不一致**全部是"少领"**（59 簇=该局最后簇=拿完即胜的**终局截断**；2 簇 residual 未解释）；**"多领"违例 0**。
- 干净单 KO 配对：normal→1（629/649）、ex→2（307/353）、megaEx→3（86/118）；偏离全由多 KO 簇归属歧义+终局截断解释（例：Dragapult ex+Dreepy 同帧双 KO→领 3=2+1 ✓；Meowth ex+Fezandipiti ex+Munkidori→领 5=2+2+1 ✓）。
- **结论：1/2/3 为严格上界，本 corpus 零反例**；等价杀伤需求 = 6 只普通 / 3 只 ex / 2 只 megaEx。[D·source-replays §3]
- 历史修正记录：61 局档案"普通 1、ex 2"未单列 megaEx；本报告以 **megaEx=3** 定案（A 反汇编 + D 实证 + C docstring 三方一致）。[D·source-replays §8]

**5.3 终局截断**

- 拿完即胜：领奖动作使对方奖赏归零的瞬间对局结束（reason 1），**之后不存在任何领取**——59/61 个"少领"残差全由此产生。胜负模拟必须把"本次击杀是否清空剩余奖赏"作边界判断，不得继续累计后续假想领取。[D·source-replays §3][A·source-binary §4]

**5.4 J 目标函数定稿（奖赏竞速目标，供 prize_solver/搜索叶子评估使用）**

1. **计价**：每只宝可梦的奖赏值 v = 1（normal）/ 2（ex）/ 3（megaEx），按卡框标志（pokemonType 语义），非按 HP/伤害。[A·source-binary §3][D·source-replays §3]
2. **目标**：J = Σ(我方已取奖赏计价) − Σ(对方已取奖赏计价)，剩余奖赏以 6 为满（bo 出场 6 张 [B·source-rulebook 一.1]）。
3. **截断**：任一领取使对方剩余归零 → 对局立即终止于 reason 1；预测中不得越过该边界继续清算。[D·source-replays §3]
4. **修正项**：Card+0x69 类 ±1（Legacy Energy 少拿 1、整局一次）与 `CoinPrize` 掷币分支按期望处理。[A·source-binary §3]
5. **清场保险项**：reason 3 占 18.5%，J 之外必须另设"场上+后备宝可梦存量"风险项（详见 §7.4），避免只算奖赏差。[D·source-replays §1.1/§10.3]
6. **多 KO 簇**：单帧可多 KO、领取可达 6 张（2+2+1 等组合合法），清算按簇不按单卡。[D·source-replays §3]

**6.2 引擎实现要点**

- 存储：中毒指示物数 `PlayerState+0x238`（0=未中毒）、睡/麻/乱**互斥单槽** `+0x239`（1/2/3）、灼伤标志 `+0x23a`；中毒/灼伤是独立标记可与旋转类并存（与规则书"标记制 vs 旋转制"一致）。[A·source-binary §0/§1][B·source-rulebook 一.4]
- Checkup 分派链（`AfterMoveTriggerStack` 0x56d80）：先按玩家序扫中毒 → `ParalyzeProc` → `SleepProc` → `BurnProc`；混乱不进 Checkup。[A·source-binary §1]
- **冲突 C2（Checkup 顺序）**：规则书=毒→烧→睡→麻 [B·source-rulebook 一.4 p15]；引擎=毒→麻痹→睡眠→灼伤 [A·source-binary §1]。裁决（A>B）：**按引擎顺序建模**（麻痹自动解除先于睡眠掷币、灼伤结算最后）；影响 Checkup 内解除/掉血/后续 KO 的时序。
- 混乱失败自伤 30：`mov ecx,0x1e` + `AddDamage` 直读；递归保险计数上限 10000（`State+0x14`）。[A·source-binary §1.5]
- 施加门槛中的 `isPreventEffect(Card)` 对应"防效果"类保护（如 Mist Energy 挡对手攻击的全部效果、Rock Fighting Energy 挡效果、Bubbly {W} Energy 解+免异常）。[A·source-binary §1.1][E·source-cards §3]
- Antique 化石（pokemonType==2）**免疫全部特殊状态**（EffectPoison/Burn/Sleep/…一律跳过）。[A·source-binary §8][E·source-cards §1]

**6.3 解除与清除**

- 中毒不自动解除（无 PoisonProc）；`ClearSpecialCondition`/`ClearSleepParalyzeConfuse` 效果清除，或换下场/离场清槽。[A·source-binary §1.1]
- 规则书：状态只作用于出战宝可梦；**进化或回到备战即全部清除**（并清除攻击带来的其他效果）。[B·source-rulebook 一.4/一.5] 引擎的"进化清状态"落实未直读到——列 §13。

**6.4 实证缺口声明（引用必读）**

- 222 game 中**毒/灼伤/睡眠/麻痹 0 样本**（施加次数均为 0），仅混乱 26 次（p0 11 / p1 15）；毒/烧每回合伤害的实测值**无读数**（字段存在、非失效）。[D·source-replays §4]

## 7. 进化 / 撤退 / 换位 / 强制补位

**7.1 进化三重时机**

1. 手牌有 "Evolves from X" 且 X **在你回合开始时已在场**才可进化（本回合进场的不能进化——对应观测字段 `Pokemon.appearThisTurn`）。[B·source-rulebook 一.5 p11][C·source-sdk §2.2]
2. 进化后视为"新在场"，**同一回合不能再进化第二层**。[B·source-rulebook 一.5 p11]
3. 双方**各自首回合禁进化**（除非卡面写明）。[B·source-rulebook 一.2 p11]
- 进化保留贴卡与伤害指示物，**清除攻击效果与全部状态**；不得使用退化型的攻击/特性（除非写明）；可进化出战或备战任意一只。[B·source-rulebook 一.5]
- 引擎实证：进化无每回合次数上限（事件层单回合最高 5 次）；三重时机的引擎落实**未单列验证**（规则书 #9 项"未知→待对照"）——列 §13。[D·source-replays §2][B·source-rulebook 二.9]
- 进化链数据：最大链深 3（basic→stage1→stage2）；`evolvesFrom` 524 条中 517 条可解析、7 条化石悬空、238 条按名歧义。[E·source-cards §2.2]

**7.2 撤退**

- 每回合 1 次（位段 0x08 + 门禁；实证 455 回合各恰 1 次）。[A·source-binary §2.1][D·source-replays §2]
- 费用：弃等同撤退费用符号数的能量，**任意属性能量各算 1**；引擎 `retreatCost`（0x75e0）含效果修正累加，费用>可用能量数则不给 RETREAT 选项。[B·source-rulebook 一.5 p12][A·source-binary §2.3]
- 禁撤条件（`MainSelect` 0x67440–0x674d1 门禁链）：后备为空 → 睡眠/麻痹 → `Card+0x20 bit0x1` → `Card+0x9b bit0x1` → Antique 化石（pokemonType==2，费用记 0 但**不给撤退**）→ 中毒+禁撤退位。[A·source-binary §2.3/§8]
- 撤退即 switch：伤害指示物与贴卡随行；撤退后新出战当回合仍可攻击。[B·source-rulebook 一.5]
- 效果换位（Boss's Orders 类）不占撤退次数，单回合事件层最高 3 次。[D·source-replays §2][E·source-cards §5]

**7.3 强制补位（TO_ACTIVE）**

- KO 后由被 KO 方从备战选新出战（SelectContext `TO_ACTIVE=4`）；引擎 `KOProc2` 0x57fc7–0x58067 **双方各自检查**：`((turn+1) ^ firstPlayer) & 1` 定检查方，任一方 active 为空即置 `State+0x2e=1` 并推 `SelectActivePokemon`。无后备可补 → reason 3 判负。[A·source-binary §2.4/§8][B·source-rulebook 一.3 p14]
- TO_ACTIVE 决策实证：93 局 833 拍（win 332 / lose 501），**win 率 0.399（61 局子集 0.388，双样本稳定）**——"被迫补位=被 KO 频率信号"。[D·source-replays §5]

**7.4 清场线 18.5% 的风险含义**

- 222 game 中 41 场（18.5%）以"无宝可梦在场"（reason 3）终局，胜方先手 19 / 后手 22。[D·source-replays §1.1]
- 单方决策 <10 的 12 个 game **全部是 reason 3 速败**（2–5 回合被清场，例：117681447 g0 败方 4 决策，Applin 40HP 前场被击穿后无宝可梦可补）——**清场是真实存在的速败通道，不是引擎故障签名**。[D·source-replays §7]
- 建模含义：必须给"场上宝可梦存量/补位储备"独立风险项；奖赏差领先但后备空虚 = 高危局面；进攻方应把"击穿后对手补位枯竭"计入胜率路径（清场线是仅次于奖赏线的第二胜利通道，占近 1/5）。[D·source-replays §10.3]

## 9. 信息结构（观测面 / 隐藏信息）与全表附录

**9.1 观测面**

## 10. 引擎实现特性（对评测方法论的含义）

**10.1 RNG：搜索层固定种子 5489;对局层不可复现【2026-10-06 运行时反证修正】**

- 【修正·置信高】`ApiAgentStart` 的 5489 常数只初始化**搜索层** MT19937;对局层 `BattleStart` 无 seed 入口,运行时实测同种子同确定性 agent(first vs first)新进程两跑结果全异(n_steps 139/274),进程内连跑亦异——**"对局字节级可复现"的原结论不成立**(与 B1 评审"洗牌 RNG 无种子入口"旧实证吻合)。评测降噪只能靠 n≥20 局数收敛+Python 侧配对随机数,引擎洗牌流不受控。[D·运行时反证 2026-10-06 裁决 A·推断]
- `ApiAgentStart` 0x137d4 以常数 **5489（0x1571，std::mt19937 默认种子）** 初始化 MT19937（624 词标准 init），索引置 624 触发再生成；导出面 `GameInitialize/BattleStart/BattleStartReverse/SearchBegin` 参数表**均无 seed**。[A·source-binary §5.2]
- 洗牌 `ShuffleDeck` 与硬币 `SelectCoinSingle` 默认走 MT19937；`ctx+0x233` 置位才走 `std::random_device` 真随机（非确定）——**疑为对局层实际熵源(Q15 未决)**;`ctx+0x231` = manual_coin（自选正反，不消耗 RNG）。[A·source-binary §5.1/§5.2/§7.2]
- **修正后的方法论含义**:①配对对比只能在 **Python 侧**做(agent 自带随机数共享),引擎洗牌流两跑不同;②"运气"仍是评测噪声,以局数收敛(≥30 局)压制;③搜索层(rollout)倒是完全确定——叶子评估 A/B 在搜索内可复现。[D·运行时反证]

**10.2 硬币结果编码与极性（冲突 C6）**

- `State+0x3c` = 上次掷币正面向上数：MT 路径**随机位 0 = 正面**（`and ebx,0x1`/`jne`/`add +1`）；手选路径选 YES=正面。所有"正面"分支判 `State+0x3c > 0`。[A·source-binary §5.1]
- `LogType.COIN` 的 `head` 字段在 MT 路径存**原始随机位**，与"0=正面"极性**相反**；SDK docstring 却称 `head=true=正面`。[A·source-binary §5.1][C·source-sdk §4]
- 裁决（A>C，且 A 自标"中"置信）：消费端以 `State+0x3c`/分支语义为准，`head` 当 raw bit 处理，待运行时对拍一次定案。工程红线：**禁止直接把 log.head 当"正面"期望计算**。

**10.3 Search API 状态机与错误码**

- 句柄体系：对局层 `Battle.battle_ptr`（BattleStart/GetBattleData/Select/BattleFinish）与搜索层 `agent_ptr`（AgentStart 惰性单例）**互不通用**；`searchId` 是状态向量下标，`SearchRelease` 回收；**同一进程多个 agent_ptr 会互踩随机上下文/状态池**（fna-016"抢原生缓冲"同源）。[A·source-binary §7.2][C·source-sdk §6.7]
- `SearchStep` 错误码：0 成功 / 1 search_id 不存在 / 2 已释放 / 3 对局已结束 / 4 `len(select)` 越界 min/max / 5 选项下标越界 / 6 选项重复 / 30 agent_ptr 损坏。`SearchBegin`：1 无效 cardId / 2 active 非宝可梦 / **99 No Basic Pokemon**（`SetupActivePokemon` 0x43ee8）/ 30 损坏。[A·source-binary §7.3][C·source-sdk §3.1]
- `select` 参数是 **option 数组下标**（不是 OptionType）；`battle_select` 非 30 错误统一 IndexError。[C·source-sdk §3.1/§3.2]
- **buffer 纠错（fna-016）**："buffer full. capacity: 7" = `FixedListBase<int,int,7>::checkFull` = **单条 Log 的 int 参数槽上限（Log.args ≤7）**，不是"搜索并发缓冲 7"。[A·source-binary §7.4]

**10.4 装载语义（部署红线）**

- 外部 agent 经 `compile(raw, path|"<string>", "exec")` + `exec(code_object, env={})`，**执行环境不含 `__file__`**（裸 dict）；从文件装载时其目录临时压入 `sys.path`（同目录 import 可用）随后弹出；**取命名空间中最后一个可调用对象作为 agent 函数**。[C·source-sdk §5.6]
- 交牌表阶段：`obs["select"] is None` 且 `obs["current"] is None`，action = 自己的 60 张卡 ID 数组；此后 action = option 下标数组。[C·source-sdk §5.2/§5.1]
- wheel 版 `sim.py` **缺 AgentStart/SearchBegin/SearchStep/SearchEnd/SearchRelease/AllCard/AllAttack 的 FFI 声明**（ctypes restype 默认 c_int 截断 64 位指针）——用搜索层前必须自行补声明或以对手工程版 sim.py 为准。[C·source-sdk §6.1]

**10.5 超时预算与 bo3 组织**

- `actTimeout=0`（单步超时关闭）+ `remainingOverageTime=600s/agent` 总预算 + `runTimeout=2000s` 全场；KE 判定式 `duration - actTimeout > remainingOverageTime` → TIMEOUT，超时方 reward=-1、对方 +1。[C·source-sdk §5.1/§5.4]
- `configuration.bo` 默认 3（BO3）；每局结束累计 `[w0,w1,draw]`；**提前终结**：`w0 > w1+remain`（或对称）即终局，`remain<=0` 无人达标 → 平（reward 0/0）；未分胜负则 `battle_start(..., reverse_player = count % 2 != 0)` 开新局——**第 2 局起第二玩家可选先/后手**（SelectContext IS_FIRST）。[C·source-sdk §5.5/§0.3]
- 对局中当前行动方 TIMEOUT/ERROR/battle_select 抛异常 → 该方 INVALID reward=-1，立即 finish（visualize+battle_finish）。[C·source-sdk §5.4]
- 可视化帧：`visualize_data()` 帧数组逐帧注 obs 副本与 action，每帧补 `remainingTime`，累计写 `env.steps[0][0]["visualize"]`。[C·source-sdk §5.5]

**10.6 帧语义（回放解析的黄金规则）**

- `viz[i].selected` = 对 `viz[i-1].select` 的应答；`viz[i].logs` = 该应答的结算；`viz[i].select` = 结算后新待选；`viz[i].action == steps[i+1][j].action`（viz 领先观测 1 步）。**错位配对会产生"一回合多次攻击"等假象**。[D·source-replays §0]
- 决策归属以"一帧 selected 恰等于某方 action"为准（93 局 0 例外）；kaggle `status==ACTIVE` 口径与动作级真值差 10.6%（3405/32193）。[D·source-replays §0/§9.4]

## 12. 数据陷阱与工程红线清单

1. **pokemonType 是卡框类别不是属系**：0=非宝可梦/1=普通/2=Antique 化石/3=ex/4=Mega ex；属系看 `energyType`。混用会导致 W/R 判断全盘错。[A·source-binary §0][E·source-cards §1]
2. **名字非唯一**：1431 卡 1196 名，238 条进化链按名歧义，7 条化石悬空——**一切按名查询改 cardId**。[E·source-cards §7.1/§7.2]
3. **damage 字段禁单用**：Comet Punch 记 0、"+N more" 记基数、效果攻击 printed base 可无意义（49/81 抗性案例）——可变伤害必须解析文本。[E·source-cards §7.5][D·source-replays §6]
